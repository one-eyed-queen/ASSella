# 3.0.0

**EXE-fingerprinter is now a terminal-only, .exe-only downloader.** The Qt desktop window and everything around it was removed.

- TUI only: a paws-style terminal interface with sixel graphics where supported and text elsewhere. SFW assets only.
- .exe-only downloads: Windows base-game depots via the steamcmd API, `-manifest-only` DepotDownloader dumps, filelist downloads of the selected `.exe`s into `%APPDATA%\exe-pawprint\<appid>`.
- Depot key sources, best to best: the local key database, your private API (HWID-bound accounts with expiry), the public Hubcap.
- Search: AppID, full name, or a few letters — merged from Steam Store, SteamDB, Hubcap and the private API; exact appid first.
- **Private API** (`https://exe-fingerprinter.vercel.app`): username + password with HWID lock on first sign-in and account expiry dates. Admin panel on the Touka Kirishima web side can create external accounts.
- **Removed:** PyQt6 desktop UI, plugins (SpaceBunny/Styx/Lobster), SLSsteam/ACCELA integration, Goldberg/GSE, Steamless, SLScheevo, achievements, workshop/DLC features, update checker, library views, `config.yaml` editing, MRC.
- NI/Linux/macOS data dirs: `~/.local/share/EXE-fingerprinter` / `%APPDATA%\EXE-fingerprinter` / `~/Library/Application Support/EXE-fingerprinter`; downloads go to `exe-pawprint`.
- ASCII art on the home menu rotates on an 8-second timer and on every return to the menu; SFW-only, 10-piece anti-repeat window.
- The external-fingerprint screen never auto-opens the file picker; Enter on the menu no longer self-triggers it — pick an .exe with P or the button, and the analysis runs in a worker. One native dialog per platform (zenity → kdialog → tkinter); a cancel ends the flow, it never chains into a second chooser.
- Depot-key resolution polls the private API first; the Hubcap bundle downloads only when the API does not cover a depot.
- Fingerprint failures now render in full (wrapped, scrollable, error-styled) instead of a 200-char mid-word truncation, and each error says *why* per source (API not signed in / lookup failed, Hubcap bundle missing, local DB miss) so the fix is obvious.
- Banner: the provided "Paws' EXE Fingerprinter" artwork ships as the header banner; minimal mode shows plain `exe-fingerprinter` branding (stale paws/SLSsteam text removed); header titles wrap instead of clipping.
- Fingerprinting a game asks first: scan lists the base game's Windows depots without downloading content, shows every .exe with size and depot, and only the ticked files are downloaded and fingerprinted. The auto-pick of whatever loaded first is gone.
- Fingerprints are now much fuller: SHA-512 and BLAKE2b-256, overall and per-section entropy, filesystem metadata (timestamps, owner, mode, inode), PE checksum verification, file/DLL characteristic names, resource inventory with languages, timedatestamp sanity notes, and a real Authenticode check — certificate chain extraction via openssl (subject, issuer, serial, validity, SHA-256 fingerprint), chain verification, and a signed-byte-range digest integrity proof that catches a single flipped byte. TOML output is valid TOML (arrays, array-of-tables) and parses with `tomllib`.
- New "fingerprint a running process" mode (external fingerprint → `r`): pick a live process, and the report merges its PID, PPID, start time, user, RSS, threads, argv (credentials redacted) and mapped modules with the on-disk image's full PE fingerprint.
- Bugfix: version info, debug directory and resource parsing never loaded (wrong pefile constants, swallowed by a bare except) — now they do.
- `scripts/test_authenticode.py` builds a synthetic signed PE on the fly (throwaway CA, openssl cms) and pins the whole signature pipeline; it is part of `prerelease_check.py` (6/6).
- One-command installers with paws parity: `./install.sh` (Linux/macOS) creates a private venv, links **`fingerprint`** and `fp` into `~/.local/bin`, installs the icon and an app-menu entry searchable as "fingerprint"; `install.ps1` (Windows) does the same in `%LOCALAPPDATA%` plus a user-PATH shim and a Start Menu shortcut ("EXE Fingerprinter"). Both are uninstallable and idempotent (re-run to update).
- Sign-in is now automatic: credentials from Settings are used at launch to refresh the session silently — no manual sign-in needed once stored.
- Fingerprint scan shows per-depot failures (with reasons) even when other depots succeeded — previously they were silently swallowed when at least one .exe was found. DepotDownloader manifest-listing timeout raised to 15 minutes for huge depots.
- Manifest listing is now offline-first: any `.manifest` this machine ever fetched (DepotDownloader's own cache, or the Hubcap bundle) is promoted into a persistent cache at `~/.local/share/EXE-fingerprinter/manifest_cache/<appid>/<depot>_<gid>.manifest` and reused without touching Steam. Steam-CM flapping no longer takes a previously-working depot down.
- Manifest misattribution eliminated: only a manifest whose filename prefix matches the depot is accepted, or a single unprefixed `.manifest` when nothing else could have produced it.

- The private API now parses Steam content manifests server-side and serves `GET /depots/{appid}/exes` (the full `.exe` listing) plus `GET /depots/{appid}/manifest/{depot_id}` (the binary needed for a real download). Signed-in users no longer need a Hubcap key on their machine or a working Steam CM connection: failed listings are recovered from the API and the API-served manifest is cached locally for downloads. End-to-end verified on GTA V Enhanced: GTA5_Enhanced.exe, PlayGTAV.exe and the redists all list and an .exe downloads and fingerprints successfully.
